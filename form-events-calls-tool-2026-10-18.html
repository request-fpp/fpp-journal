События формы в PostHog и инструмент для звонков, 18.10.2026

Задание чата, переданное Денисом: две вещи в «окне GBP/PostHog». Первое: считать в PostHog открытие формы Request Service и отправленные заявки. Второе: инструмент, который одной командой собирает таблицу звонков по дням.

1. События формы

Что сделано. На живом сайте с 18.10.2026, 23:49 форма Request Service отправляет в PostHog два события:

  • form_open: форма открылась (по любой кнопке Request или по ссылке с #request);
  • form_submit: сервер ответил, что заявка ушла в Telegram. Событие отправляется только после этого ответа; если заявка не прошла, события нет.

У обоих событий два свойства: page (адрес страницы) и office. Имени, телефона, почты, адреса и текста заявки в событиях нет.

office берётся из страницы, на которой открыли форму:

Страница office
Frisco и города, которые обслуживает офис Frisco (McKinney, Prosper) frisco
Plano plano
Allen (его обслуживают оба офиса) both
Все остальные страницы, главная тоже none

Сверка с живым сайтом перед выкладкой. Сравнил все 63 страницы (64-й адрес это переадресация /blog/author/admin/). На каждой странице меняются только три места формы: пометка офиса на окне формы, строка, которая отправляет form_open, и строка, где form_submit теперь несёт офис. Ничего другого не меняется. Значения офиса: none на 58 страницах, frisco на 3, plano на 1, both на 1. Проверка сайта: 34 из 34. IndexNow не запускался: изменился только код формы, текст страниц тот же. Для этого в tools/deploy.sh добавлен флаг NO_INDEXNOW=1.

Проверка, что события приходят. Задание просило проверить на черновом адресе. Черновой адрес закрыт входом Cloudflare Access по почте Дениса, войти туда я не могу. Поэтому ту же сборку я проверил локально, на этом Mac, по адресу 127.0.0.1: - PostHog на время проверки был включён для этого адреса; - форма открыта кнопкой Request на странице Frisco; - ответ сервера в этой вкладке подставлен, поэтому ничего не ушло ни на сервер, ни в Telegram; - через несколько секунд в PostHog пришли form_open и form_submit, оба со страницей /plumber-frisco-tx/ и офисом frisco, без полей формы.

Эти два тестовых события записаны с адресом 127.0.0.1:8799, поэтому в отчёты по fppplumbing.com они не попадают. На черновик сборка с PostHog выкладывалась только на время проверки и потом пересобрана обратно без него.

Почему заявки 18 октября нет в PostHog. Событие form_submit в коде было и раньше, с тем же условием: только после ответа сервера. Скорее всего, у отправителя PostHog не работал. Возможных причин три: - Отключено нами: браузер когда-то открывал ссылку ?fpp_optout=1. Так отключают визиты свои и команды; если заявку отправлял Денис со своего телефона, это объясняет всё. - Блокировщик рекламы: он часто режет PostHog. - Очень старый браузер.

На локальной копии весь путь от кнопки до события сработал.

2. Инструмент для звонков

tools/calls_report.py <дата от> <дата до>, только чтение. По каждому дню (время Далласа): - показы в картах, звонки с карточек и переходы на сайт с карточек, для Frisco и Plano отдельно и вместе (Business Profile Performance API); - клики из Google на сайт (Search Console, весь сайт; у предварительного дня звёздочка); - просмотры сайта без ботов, клики по кнопке звонка, открытия формы и заявки (PostHog).

Потом то же за те же дни месяц назад: для октября это сентябрь, и сумма берётся только по дням, за которые есть цифры в самом периоде. Результат пишется в exports/calls/calls-<от>-<до>.csv и docs/calls-<от>-<до>.md и публикуется в журнале как страница calls-report: постоянный адрес показывает последний прогон, плюс копия с датой.

Проверка на 1-18 октября. Цифры совпали с отчётом calls-drop: - за 1-15 октября показы в картах 342, звонки с карточек 23, переходы на сайт 35; - за 1-15 сентября 333, 25 и 27; - клики из Google по дням те же.

Одно отличие. Просмотры сайта 18 октября в инструменте 19, в отчёте calls-drop было 23: инструмент считает без ботов, там считались все. Ещё за 18 октября появились клики из Google: 4, предварительно.

Откуда что берётся: - профили: через вход владельца профилей, только чтение, Plano только для сравнения; - Search Console: через сервисный аккаунт только для чтения; - PostHog: через ключ только для чтения, тот же, что у подключения PostHog в Claude Code. Ключ читается из настроек на этом Mac и нигде не печатается.

Команда на вторник (кнопка Run в приложении):

cd ~/Projects/fppplumbing-site && python3 tools/calls_report.py 2026-10-16 2026-10-21

Цифры профилей Google отдаёт с задержкой в 2-3 дня. Если запустить во вторник 21 октября, последние 2-3 дня покажут «нет данных». Полная картина за 16-21 октября будет к пятнице 24 октября, тогда ту же команду стоит запустить ещё раз.
